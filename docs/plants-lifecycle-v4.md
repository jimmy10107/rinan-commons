# 植物形態室 v4｜SVG 生命週期與預先解析 3D

Owner：Codex。Deadline：本次交付。Lead：Digital & Data。
基線：575f2055。Checkpoint：SVG 輕量化 → 預備五個階段 → 冷載入與快取測試 → GitHub Pages。
DoD：第一時間可見 SVG；約 6.5 秒播放五段生長影格；並行準備目前植物的五個輕量 3D；階段切換重用已解析模型；保留放大精細化與手機操作。

## Decision

使用者認為 v3 仍太慢，最新要求取代「先看到可操作 3D 才有內容」的流程：先用 SVG 影格播放生命週期，播放期間積極準備 3D。使用者可略過或選階段，不強制等滿 6.5 秒。

## Implementation

- 保留原 30 SVG 下載；另建 30 個真正向量、沒有嵌入點陣圖的播放影格。以原有器官輪廓簡化與顯示尺度取樣，合計從約 30.2 MB 降為約 1.61 MB，最大單檔 171 KB。芋頭五張合計約 13 KB。
- SSR 即輸出第一張 SVG，無需等 Three.js、WebGL 或 GLB。五張影格各約 1.3 秒、短淡入切換，總長約 6.5 秒；這是五個觀察姿態的播放，不是連續生理形變。
- 播放與實際 3D 選擇分離，播放影格不觸發五次 3D 場景切換。
- 當前階段優先載入，另以兩個背景工作槽準備同物種其餘輕量階段；相同 URL 合併進行中的下載／解析。
- 新增已解析 Group 與材質編譯快取，五階段切換直接重用；目前物種之外的準備作業會取消，物件與貼圖釋放。一般最多保留六個已解析模型，詳細特寫進入時會淘汰舊模型。
- 取消每次階段切換後無條件再下載精細模型；全株或特寫放大超過約 1.45 倍，才補載較精細模型。手選細節仍可用。
- 畫面播放進度是動畫時間；「3D 準備 n/5」來自實際完成解析／材質編譯的狀態，不以計時器冒稱載入完成。
- 慢網路保留可切換 SVG；不以滿版模糊等待框遮住影格。使用者可選靜態模式。首次失敗仍有重試，單次準備設定 15 秒期限。
- Save-Data／低速連線不大量預備其餘階段；reduced-motion 預設略過自動動畫，保留手動重播。
- 原本跨頁閒置預載、完整 GLB／SVG／PNG 下載、六植物、照片、全株與特寫均保留。

## Evidence / Limits

- tests/browser-plants-v4.mjs：六植物共 30 個已準備階段切換，不新增模型下載；縮放補載、6.5 秒播放、360–1440px、手機與低流量模式。
- tests/browser-plants-cold.mjs：六植物分別用全新瀏覽器情境，10 Mbps、80ms latency、2 倍 CPU 降速，量測首影格與五階段準備時間。
- 報告與截圖：docs/qa/plants-v4。量測是 Chromium 軟體 WebGL 與手機視窗模擬，不是實體手機保證。
- 「五階段準備」指目前所選植物的輕量 3D；不把所有六植物的全品質素材下載塞進 6.5 秒。實際時間依網路與裝置，畫面顯示真實完成數。
- 沒有新增實株掃描。原 SVG 是向量形態輪廓，細緻紋理與立體觀察由既有 GLB 提供。

## Reproduction

`python scripts/build-lifecycle-svg.py` 需 Shapely；原始 SVG 留存 public/plants/svg，播放版寫至 public/plants/frames。正常部署不需 Python 或重建影格，直接使用已驗證素材。
既有內容、公開素材檢查與 GitHub Pages 部署流程保留。
